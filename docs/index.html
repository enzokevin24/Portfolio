Animaciones implementadas (GPU 60 fps)

  • Entrada escalonada del Hero: @keyframes heroFadeUp y heroCardIn con variable --hero-delay.
  • Aparición de bloques al scrollear: IntersectionObserver detecta cada .reveal-block y agrega .is-visible.
  • Barra superior de progreso: Escala horizontal (transform: scaleX) sincronizada con requestAnimationFrame.
  • Microinteracciones: Elevación suave en tarjetas, zoom sutil en ilustraciones y filtros interactivos de proyectos.
  • Accesibilidad: Respeta prefers-reduced-motion: reduce desactivando movimiento excesivo automáticamente.

Cómo funciona el IntersectionObserver

const revealObserver = new IntersectionObserver(
  (entries, observer) => {
    entries.forEach((entry) => {
      if (entry.isIntersecting) {
        entry.target.classList.add("is-visible");
        observer.unobserve(entry.target);
      }
    });
  },
  { threshold: 0.12 }
);

Además, JS agrega la clase .js-ready al <html>; si por alguna razón JS estuviera desactivado, todos los bloques permanecen visibles.

Registro de Uso de IA (Resumen de bitacora_ia.md)

Consulta 1 — Estructura HTML y Privacidad

Objetivo: Armar la estructura semántica con proyectos reales (EduEventos en Tkinter, Autito seguidor de línea y cursos de barbería).

Decisión propia: Omitir teléfono y edad exacta del CV, y crear ilustraciones SVG reales en lugar de rutas rotas.

Consulta 2 — Paleta Roja/Blanca, Animaciones y Docs

Objetivo: Aplicar diseño rojo y blanco con degradados, animaciones de entrada/bloques y documentación en .md + .html.

Decisión propia: Usar JavaScript nativo sin frameworks externos para poder explicar cada función fácilmente.

Guía rápida para explicar el código al docente

Si te preguntan... Qué responder y dónde mostrarlo
¿Dónde están los colores y degradados? En css/estilos.css dentro de :root (--red-900 a --red-50 y --gradient-brand).
¿Cómo hiciste las animaciones de los bloques? Con .reveal-block en CSS y IntersectionObserver en js/script.js que agrega .is-visible al aparecer en pantalla.
¿Por qué EduEventos no corre en vivo en el sitio? Porque GitHub Pages aloja sitios estáticos (HTML/CSS/JS) y no ejecuta Python; por eso se documenta y muestra con su maqueta visual.
¿Cómo protegiste tus datos personales? No se publicó teléfono ni dirección particular; solo correo, ciudad general y disponibilidad horaria.

Pasos para publicar en GitHub Pages

  1. Creá un repositorio público llamado exactamente tuusuario.github.io.
  2. Subí los archivos manteniendo index.html en la raíz junto a css/, js/, assets/, docs/, README.md y bitacora_ia.md.
  3. No subas la carpeta MATERIAL/ si contiene tu CV PDF con número de teléfono privado.
  4. Abrí Settings → Pages en GitHub.
  5. En Source elegí Deploy from a branch, seleccioná main y /(root), y tocá Save.
  6. Esperá unos minutos y abrí https://tuusuario.github.io.
